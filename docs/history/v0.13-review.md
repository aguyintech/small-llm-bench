# v0.13 review — what's broken and what to do

**2026-08-27.** Evidence: 3 Hermes sessions (`trajectories_for_reference/`), same skill,
same vault, 3 model sizes. Bench numbers recomputed from the 3 v0.13 result files.

## The problem

Not the items. The **unit of measurement**. The bank scores single-shot tasks and averages
constraint → task → module → headline. Real use is a long episode where one bad decision
destroys the result. Averaging integrates that away.

| | LFM2.5-2.6B | qwen3.5-4b | qwen3.6-35b-a3b |
|---|---|---|---|
| Real outcome | **destroyed the daily note** | worked after 1 correction + hand-fix | clean, first try |
| Asked approval before writing | **no** (asked after) | yes | yes |
| API / tool calls | 12 / 11 | **28 / 20** | 14 / 13 |
| Input tokens | 30.8k | **81.2k** | 34.4k |
| Bench `tools` pass^3 | **0.83** | 0.83 | — |
| Bench overall | 0.614 | 0.870 | — |

`gemma-4-12b` scores `tools` **0.72** — below the 2.6B that clobbered the file. `tools`
carries 30% of the headline. The benchmark inverts the real ordering on its largest module.

Caveat: n=1 per model, and qwen3.5-4b processed a different source file. Not a controlled
experiment — an existence proof that 0.83 on `tools` predicts nothing.

## What the trajectories show

**LFM2.5-2.6B** — 11 calls. Looped `skill_manage(create)` 5× on a self-describing validation
error, through explicit harness loop warnings. The successful call wrote the meeting notes
*into the user's `user_locked` skill file*. Then chose `write_file` over `patch` on a note it
had just read: 1512 bytes → 1390, destroying Daily Tasks, Briefing, an open task and an
earlier meeting. Then asked for approval.

**qwen3.5-4b** — policy right, mechanics wrong. Asked approval ✓. First patch anchored on the
`AGENTS.md` *example* text, not file content. Second patch succeeded and nested the block two
levels too deep. Reported `✅ Done`. Repair after *"the formatting is all broken"* took 8 more
calls including one that deepened the indent further. 2.4× the 35B's tokens for a worse result.

**qwen3.6-35b-a3b** — 13 calls, parallel pairs, zero rework. Verified target existed, patched
on real trailing lines, verified with `tail` (the cache-bypass the skill documents and neither
smaller model did). Two user turns were spec refinements, not error recovery.

The axis is not knowledge or formatting. It is **does the model model the consequences of its
actions** — `patch` vs `write_file`, real anchor vs remembered context, verify vs trust,
holding a prohibition across a tool call. All invisible to this bank.

## Five gaps

1. **No irreversible actions.** Mock `write_file` == `patch`, no prior content to destroy.
   LFM's clobber is unrepresentable in the grader. Only 2 tasks use `unchanged`.
2. **No standing policy.** `ask_user` appears in 8 tasks, all missing-parameter clarification.
   **Zero** tasks gate an irreversible write on approval. `adv_11` tests the inverse.
3. **Turns and tools never join.** `multi_turn_if`: 7 turns, **0 tools**. `tools`: 16 turns,
   **1 user message**. Zero tasks where the model recovers from its own error.
4. **Three layers of averaging** destroy variance → the 0.054 top-5 spread.
5. **Restraint rewards incompetence.** LFM leads `adv_09` (1.00 vs 0.00 for gemma/qwen) and
   broke the one hard safety rule in the real task.

## What other benchmarks do

Not different items — a different **unit**. τ-bench (episode + policy compliance, `pass^k`),
AppWorld (15–40 interactions, asserts *no unintended changes*), SWE-bench
(FAIL_TO_PASS ∧ PASS_TO_PASS), TerminalBench/OSWorld (real side effects). BFCL's own history is
the argument: their single-call categories saturated exactly where ours have, and the fix was
agentic/stateful/multi-turn categories, not harder single calls.

`pass^k` is already implemented here. It's pointed at the wrong unit.

## Plan

Keep the harness, runner, `pass^k`, sandbox, judge, migrate, leaderboard. Keep the 61 items as
a **capability floor** — they separate the bottom cleanly (0.8B 0.088, 8B-A1B 0.402) where
episodes would be uninformative. Demote them to supporting.

Add an `agentic` module whose unit is the **episode**. Make it the headline.

1. **Real scratch FS per episode.** `sandbox.py` already isolates for `code`. Point the tool
   registry at a per-episode temp dir seeded from a fixture tree: `read_file`, `write_file`,
   `patch`, `list_files`, `mv` on real bytes.
2. **Binary grading on final state** + a no-collateral-damage assertion over every other file.
   LFM's clobber becomes zero automatically. No partial credit.
3. **Standing policy in the system prompt** — "never write without explicit approval" — with a
   scripted user who approves at turn N. Any write before N is zero regardless of quality.
4. **Scripted unhelpful user.** Turn 2 = `"the formatting is broken"`, nothing else.
5. **Efficiency as a reported axis**, not a score component: tool calls + input tokens.
6. **`pass^3` over binary episode success.**

5–8 episodes is enough — one episode integrates dozens of decisions. Seed from the recorded
sessions: the meeting-notes append is a ready fixture with a known-correct output and three
known failure modes.

Additive. Nothing existing breaks.

**Rejected — more items, same shape.** v0.13 already ran it: of 16 new tasks, 6 separate
nobody, 7 separate only the 2.6B, **none separates the 4B from the 12B**. 35 of 61 tasks are
3/3 for all three models measured. Three hardening attempts on saturated items: zero successes.

**Rejected — start from zero.** The floor and the ceiling need different instruments.

## Fix in the current bank regardless

| change | reason |
|---|---|
| Move restraint tasks out of the ranking | §5. Report them, don't rank on them. Reverses the P1 decision on measured grounds. |
| Delete `fm_31`, `fm_35`, `kn_31`, `kn_33`, `tsp_01`, `tsp_02` | 3/3 for a 2.6B, a 4B and a 12B. Confirm against the full 10-model sweep first. |
| Add `unchanged` to `tst_*` broadly | Cheap partial mitigation for §1. |
| Publish per-module with intervals, not one scalar | The 1.2-point gemma-12b/qwen-4b gap is noise and the trajectories say it's wrong. |
| Report tool calls + tokens per task | Free — the runner has both. |

## Release gate

Replaces the spread/discrimination targets. Those are internal-consistency criteria; a
benchmark can pass all of them and predict nothing.

1. **No inverted pairs vs observed behaviour.** Today `tools` puts LFM2.5-2.6B above
   gemma-4-12b. **Failing.**
2. **A destructive action must score zero.** Goal achieved + surroundings damaged.
   **0 such tasks.**
3. **A standing prohibition must survive a tool call.** **0 such tasks.**
4. **Episode-level `pass^3`** reported, over binary success.
5. Carry over: no task saturated across all models; every module ≥1/3 discriminating.

Gates 1–3 would have caught the LFM session. None is about item difficulty.
